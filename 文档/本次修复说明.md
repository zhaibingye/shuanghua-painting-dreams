## 已修复的问题

| 问题 | 触发场景及影响 | 修复 |
| --- | --- | --- |
| 开发启动器参数错误 | `npm run dev` 把命令、参数数组、目录和标签拼进了 uv 参数，后端无法正确启动 | 使用平铺的 uvicorn 参数，验证自定义端口与 Vite 代理 |
| 恢复默认设置无效 | 点击按钮只返回对象，没有调用 Zustand 的 set，界面和持久化都不变 | 实际更新 store，并由既有订阅保存设置 |
| 本地数据更新竞争 | 同时重命名、更新基图或更新任务状态，后一次写入可能丢失另一项修改；删除时也可能被迟到的写入恢复 | 对话、消息、视频任务的读改写使用同一个 readwrite 事务 |
| 历史查询结果串入新对话 | 快速切换对话或数据库多次刷新时，旧查询较晚返回并覆盖新结果 | 查询和结果绑定，卸载时停用回调，只采纳最新一次刷新 |
| 视频提交状态管理不完整 | 本地保存完成前可重复提交；保存失败没有捕获；旧请求完成后可能清掉新对话草稿 | 提前同步锁定提交，统一捕获保存与请求错误，清理草稿前核对对话 |
| 图片 SSE 连接未及时结束 | 已收到完成事件仍等待连接关闭；事件处理失败时 reader 没有释放 | 完成事件后立即返回，在 finally 中取消 reader 并释放锁，兼容分片 UTF-8、CRLF 和 EOF 尾事件 |
| Responses 流提前结束被误判成功 | 收到图像工具输出后断流，但缺少 response.completed | 必须收到完整响应完成事件才发送本站完成事件 |
| 视频成功响应缺少输出 | 字节或 xAI 返回成功状态但没有视频对象时，前端停止轮询；xAI 缺 URL 还被误报审核失败 | 返回结构化上游响应错误，使轮询进入重试；仅明确审核拒绝时报告审核失败 |
| 首个独立 Key 被首字符截断 | 无全局 Key 时，在独立 Key 输入框逐字输入，首字符立即被提升为全局 Key，输入框随之关闭 | 先编辑完整草稿，在失焦或关闭弹窗时提交；兼容 Escape 关闭 |
| 遮罩撤销和重做记录重复 | React StrictMode 重复调用状态更新函数，嵌套的另一项 setState 产生重复历史 | 用同一个历史状态进行纯函数更新，并补充按钮可访问名称 |
