# 霜华绘梦对话式系统架构设计 v2

## 1. 目标

霜华绘梦是一个本地优先、后端无状态的多供应商图片和视频创作工具。

本次架构升级的核心目标：

1. 用统一的对话模型替代图片/视频双栏工作台。
2. 支持多个独立对话和浏览器本地历史。
3. 为 OpenAI Images、OpenAI Responses、Gemini、xAI 提供正确且不同的图片多轮语义。
4. 为 OpenAI 两种格式提供 SSE 和渐进图片。
5. 保持 API Key、媒体结果和会话状态不进入服务端持久化。
6. 保留安全 Base URL、SSRF 防护、长请求和视频轮询能力。

## 3. 状态边界

### 3.1 浏览器保存

- API 设置和 Key。
- 对话元数据。
- 用户和助手消息。
- 用户本地输入图片 Blob。
- 最终生成图片 Blob。
- Gemini `thought_signature` 和模型 parts。
- OpenAI Responses `image_generation_call` ID 与图片引用。
- 视频任务、轮询状态、结果 URL。

### 3.2 浏览器不保存

- Partial Images。
- Base64 网络响应副本。
- 正在传输的 SSE 缓冲区。

### 3.3 后端不保存

- 对话。
- API Key。
- 输入和输出图片。
- Responses ID。
- Gemini 历史。
- 视频任务 ID。

后端只在单次请求生命周期内持有转换所需数据。

## 4. 对话约束

每个对话固定：

- `mediaKind`。
- `apiFormat`。
- `baseUrl` 快照。
- `modelId` 快照。

这样可避免：

- Responses/Gemini 上下文跨供应商串线。
- 修改全局设置后破坏已有对话。
- 视频任务轮询使用错误 Base URL。

本轮参数可以变化，并在修改后成为该格式的新默认值；对话连接与模型不变。

## 5. 图片多轮策略

### 5.1 OpenAI Images 与 xAI Image

这两种 API 本身是无状态图片端点，因此对话状态由客户端实现：

```text
无历史最终图片 + 无当前附件 → generation
无历史最终图片 + 有当前附件 → edit
有历史最终图片              → latest active image + current references → edit
```

- 最近成功轮次的第一张非思考图片自动成为活动基图。
- 用户可显式选择同轮其他结果。
- 新附件补充到活动基图之后。
- 新建对话表示从零生成。

### 5.2 OpenAI Responses

隐私约束：`store: false`。

因此不使用依赖上游存储的 `previous_response_id`，改为显式历史重放：

```text
user message
image_generation_call (id + status + result)
user message
image_generation_call
current user message
```

浏览器从 IndexedDB Blob 临时恢复 Data URL，后端剥离前缀并映射为 `result` Base64。请求结束后不保存 Base64。

### 5.3 Gemini

浏览器回传完整成功对话历史：

```text
contents = [
  user parts,
  model parts + thought_signature,
  user parts,
  model parts + thought_signature,
  current user parts
]
```

普通输出与思考输出均保留顺序和签名。UI 将思考内容放在可折叠的次级区域。

## 6. SSE 架构

### 6.1 上游流

Safe HTTP Transport：

- 关闭自动重定向。
- 重新验证每个 307/308。
- 使用增量 UTF-8 解码器解析 SSE。
- 基于空行切分事件，不使用存在行长限制的 `readline()`。
- 支持包含大型 Base64 的单行 SSE data。
- 响应总大小受 `SHUANGHUA_MAX_JSON_RESPONSE_BYTES` 限制。

### 6.2 标准化流

Provider 事件被转换为：

```text
turn.started
image.partial
text.delta
image.completed
turn.completed
turn.failed
```

前端无需理解 OpenAI 两种上游事件命名差异。

### 6.3 前端任务生命周期与取消

图片流由应用级内存任务协调器按 `taskId / conversationId / assistantMessageId` 管理，不再由当前路由页面持有。

```text
切换对话
  ↓
ChatPage 只切换展示内容
  ↓
全局任务协调器继续读取原 SSE
  ↓
最终结果写入原对话 IndexedDB
```

只有用户显式点击停止时才执行：

```text
cancelImageTask(taskId)
  ↓
对应 AbortController.abort()
  ↓
浏览器关闭该任务的 FastAPI SSE
  ↓
FastAPI async generator 被取消
  ↓
aiohttp 上游响应上下文关闭
```

该轮标记 `stopped`，Partial Image 被释放。刷新或关闭浏览器仍会中断所有内存图片任务，本版本不提供跨页面生命周期恢复。

## 7. 图片持久化事务

```text
SSE image.completed
  ↓
Web Worker Base64 → Blob + 尺寸
  ↓
等待 turn.completed
  ↓
同一 IndexedDB 事务：
  - 写入所有最终 Asset
  - 更新 Assistant Message
  - 写入 Provider State
  - 更新 Conversation.activeImageAssetId
```

思考图片也会持久化，以便 Gemini 下一轮原样回传，但不会自动成为编辑基图。

## 8. 视频对话

普通视频轮次完全独立：

- 不继承上一轮提示词。
- 不继承上一轮输入图片或 URL。
- 不继承上一轮模式。
- 不自动把上一轮视频作为输入。

显式操作例外：

- 字节尾帧续写：用户点击后，把 `lastFrameUrl` 写入新轮次首帧字段。
- xAI 扩展：用户点击后，把 `videoUrl` 写入 `/videos/extensions` 请求。

视频创建后，浏览器保存任务并由全局 Poller 查询。切换对话不停止轮询。

## 9. Seedance service_tier

`doubao-seedance-2-5-*` 与 `doubao-seedance-2-0-*` 不发送服务等级字段：

```json
{ "service_tier": "default" }
```

因此能力模型区分：

```ts
serviceTiers: ["default"]
serviceTierParameter: false
```

含义是产品处理模式为默认在线，但请求字段必须省略。

Adapter 只有在 `serviceTierParameter === true` 时才序列化该字段。当前明确发送字段的模型为支持 `default/flex` 的 1.5/1.0 系列。

## 10. SSRF 与密钥安全

沿用原安全架构：

- Base URL 静态验证。
- 自定义公网 DNS Resolver。
- 禁止私网、环回、链路本地、元数据地址。
- 禁止跨 Origin 重定向，防止 Bearer Key 泄漏。
- 禁用环境代理和 DNS 缓存。
- 日志不记录 Prompt、Key、Data URL 和完整素材 URL Query。

## 11. 部署

生产环境由 FastAPI 提供 Vite 资源和 API。Nginx 整站代理到 `127.0.0.1:3002`。

SSE 必须：

```nginx
proxy_buffering off;
proxy_request_buffering off;
proxy_read_timeout 620s;
proxy_send_timeout 620s;
```

## 12. 验收标准

- 六种 API 格式出现在元数据中。
- OpenAI Responses 默认模型为 `gpt-5.6-luna`。
- Responses 请求固定 `store: false` 且不使用 `previous_response_id`。
- OpenAI 两种格式支持 SSE 和 0～3 张 Partial Images。
- Gemini 完整历史和签名可恢复。
- OpenAI Images/xAI 自动编辑活动图片。
- 视频普通轮次相互独立。
- Seedance 2.0 不发送 `service_tier`。
- 对话、图片和任务仅保存在浏览器。
- Pytest、Ruff、mypy、ESLint、TypeScript、Vitest、build 全部通过。
